# Caspy QA plan — 14 November 2026

Status: **plan only. Nothing in this document has been executed.** Stage 1 findings
(Appendix A) come from reading the code and docs. They are hypotheses until a test in
section 3 reproduces them. The plan was written before any Stage 3 run and will not be
edited after the fact to match results; results go in `docs/qa-report-2026-11-14.md`.

Source of truth used: `.kiro/steering/project.md`, `PRD.md` (sections 1–22, appendices
and the 8 November amendments), `docs/render-deployment-2026-11-10.md`,
`docs/cloud-deployment.md`. **`PRD.md` has no section 23**, although its header, section
13.4 and the steering file call section 23 authoritative for hosting (finding R-25). The
10 November hosting facts were therefore taken from the Render deployment note and the
steering file.

Working tree at review time: branch `fix/render-container-20261110`, HEAD `4e47723`
(same commit as `origin/main`). Uncommitted and left untouched:
`scripts/candy_store.py`, `scripts/space_schnell.py`, `scripts/test_candy_store.py`,
`scripts/test_space_schnell.py`. Untracked: `.kiro/specs/`, `PRD-persuasion-benchmark.md`.

## 1. Scope

In scope:

- Accounts, sessions, throttling, CSRF/origin handling, idempotency.
- Wallet sign-in (SIWE) and wallet-to-account linking.
- The heist: attempt limits, prompt limits, judge outcomes, daily retry rules, restart recovery.
- Research consent, campaigns, human review, releases, access grants, export, withdrawal, retention.
- Candy: reward gate, grading, generation consent, retry/quota/budget logic (including the
  uncommitted `candy_store.py` / `space_schnell.py` changes), token handling.
- Vouchers, minting, collection, marketplace, prompt access (on a disposable local chain only).
- Social friends.
- Frontend behaviour: mobile 375 px, keyboard, contrast, landmarks, loading and error states.
- Vercel proxy, Docker image content, hosted read-only smoke checks.
- Accuracy of UI and documentation text against the code.

Out of scope:

- **Persuasion benchmark** (`.kiro/specs/persuasion-benchmark/`, `PRD-persuasion-benchmark.md`).
  Every task in its `tasks.md` is unchecked and no code references it. It is not tested.
- Solidity audit-level review (the existing Foundry tests are run, not reviewed).
- Load and capacity testing, mainnet, payments, email verification, password recovery
  (documented as not built).
- Real model quality, judge calibration, and real image generation (needs paid or real providers).
- Any write to the hosted site, Render, Vercel, Supabase, or a public chain.

| ID | Constraint | Effect |

| E-6 | `CASPY_RUN_SUPABASE_TESTS=1` creates and drops a random `caspy_test_*` schema on the live Supabase project. | That is a change to Supabase. Those tests stay **skipped** unless you point them at a non-production database. |

Legend for the **Mode** column:

- `A` existing automated test (Python `unittest`, `node --test`, Foundry, pytest).
- `A+` new automated probe. Written to `scripts/qa_probes_2026_11_14.py` (name chosen so
  `test_*.py` discovery and CI do not pick it up). Added only if you approve; see section 5.

- `HR` hosted, read-only GET.
- `BLK` blocked by a hard rule or by something I do not have.

"Expected" describes **correct behaviour per the PRD**. A case marked **(expected to fail today)**
is one where Stage 1 predicts the product does not meet that expectation.

## Appendix A — Stage 1 review findings

All findings come from reading code. Line numbers refer to the working tree at review
time. No finding was confirmed by running anything. **No critical finding.**

What I checked and found sound: no path lets the actor's text, or a request field, set
`won`, sign a voucher or mint (`Games.apply_verdict`, `heist_api.py:256-259`, is the only
writer of `won`; `nft.voucher` requires `won`, a ready image, a wallet linked to the
account, and ownership). Attempts are decremented under a per-heist non-blocking lock
before the actor call (`heist_api.py:213`) and refunded only when no reply was produced.
Ownership checks exist on account, heist, candy, reward, avatar, prompt, social,
campaign, review, release, order and export routes. Research capture checks consent,
withdrawal and retention inside the same transaction (`platform_store.py:296-300`), and
exports re-check consent on every request (`eligible`, `platform_store.py:374-376`). The
Space token is sent only to the pinned origin and redirects are disabled
(`space_schnell.py:62`, file URL check at `:110-113`).

### High

**R-01 Sign-in throttle uses the proxy's address.**
`platform_store.py:158-166` counts attempts `WHERE ip=? OR email=?`, limit 20 per 10
minutes, inserted **before** the password check. `platform_store.py:468` passes
`handler.client_address[0]`. `runtime_config.py:1` states it trusts no forwarded
headers, and `frontend/api/proxy.ts:32` forwards only cookie, origin, content-type,
idempotency-key and accept. Behind Vercel and Render the peer address is the proxy's,
not the user's.
Scenario: anyone sends 20 login requests with random emails; every user then gets 429
for up to ten minutes. Separately, 20 failed logins for one email lock that person out
(any address). Normal sign-ins by many users also share the same bucket.
Not confirmed on the hosted stack (writes forbidden).

**R-02 Unauthenticated endpoints spawn Node and scan the chain.**
`heist_api.py:362` (`/market/listings`) and `:367` (`/market/history`) run before any
auth check and call `nft.call` (`nft_game.py:62-63`: one `node` process per request,
45-second timeout). `history` (`nft-bridge.mjs:41`) reads `CandySold` logs from
`deployment_block` in 200-block pages, 4 at a time (`chainEvents.ts`). From block
55,968,978 on 8 November that is about 1,300 pages after six days, more than the
timeout allows (assuming a block about every 2 seconds), so it fails and still burns the
45 seconds. `ThreadingHTTPServer`
starts a thread per request with no limit; Render Free has 512 MiB.
Scenario: 20 parallel `GET /api/market/history` spawn 20 Node processes and RPC fan-out;
the API is starved or killed, and in-flight turns become `void`/`pending_review` after
the restart. The UI no longer uses `/market/history`.

### Medium

**R-03 The maintenance hook can stop the server.** `heist_api.py:596-598` sets
`server.service_actions` to run `games.prune()` and `platform.purge()`.
`serve_forever` calls it with no exception handling; `purge` (`platform_store.py:453-460`)
opens a database connection that raises `DatabaseError` on any connection failure
(`database.py:127`). Scenario: one Supabase hiccup at the 60-second purge tick ends
`serve_forever`, the process exits, `cloud_start.py` raises "A required service exited",
Render restarts the container (cold start, up to two minutes of gateway wait).

**R-04 Judge output and model routes are returned to the player.**
`apply_verdict` stores `verdict`, `confidence`, `category`, `exploit_flag`,
`candy_scores`, requested/served model routes and prompt/rubric hashes
(`heist_api.py:256-263`); `Platform.decorate` returns the whole game
(`platform_store.py:292-295`) from `GET /game/session/{id}` (`heist_api.py:427-429`) and
`/game/review`. `test_platform_http.py:149` asserts `evaluations` is present, and
`frontend/src/lib/game.ts:3` types it. Scenario: a player reads `confidence: 0.74` after
turn 1 and tunes turn 2 against the 0.8 threshold. PRD FR-C4 says Caspy never reveals the
rubric or win criteria; the hosted route names also contradict the steering note that
gateway names were removed from the UI.

**R-05 One model decision is the only win gate.**
`apply_verdict` (`heist_api.py:258`) and `_reserve_win` (`candy_store.py`, verdict check
before `INSERT`) apply thresholds to fields the judge model wrote (`exploit_flag`,
`category`). PRD 5.3 FR-J5 and 7.4 require a denylist, a similarity check against earlier
winners, a win-rate governor with `pending_review`, canary and leakage checks; none of
these are in the files reviewed, and risk R1 in PRD section 17 depends on them. Scenario:
a prompt that makes the judge confident and clean wins every time it is replayed, each
win reserves one of the 1,000 candies and unlocks a voucher. Testnet only today.

**R-06 A resumed heist ignores the consent the player just chose.**
`Games.create` returns the existing protected heist (`heist_api.py:175-179`);
`associate_game` finds an existing `contributions` row and does nothing
(`platform_store.py:241-265`); the Play page sends the checkboxes
(`App.tsx:233`) and hides the consent panel once a session exists. Scenario: a player
starts a heist with research and commercial consent on one device, then on another
device selects "play privately" and presses start. They get the same heist, still
consenting, with no message. Their later prompts are captured for the campaign until
they withdraw.

**R-07 Replay and judge calls are unbounded; the 100/day cap cuts the wrong people.**
Contributors skip the heist cap (`heist_api.py:184`) yet their sessions count in
`daily_count` (`:183`), so heavy contributor replay makes `Local session limit reached`
for every non-contributor. `/game/review` (`:508-514`) and `/game/turn` have no rate
limit, and each call can hit the judge or actor. PRD 9.1 and goal G4 ask for per-IP
limits and bounded cost per wallet. Hosted actor and judge use the shared Gemini free
tier, so one account can exhaust it for everyone.

**R-08 Wallet sign-in challenges can be exhausted by any account.**
`nft_game.py:74-84` stores challenges keyed by the client-chosen `caspy_local` cookie,
globally capped at 1,000 for 5 minutes, with no per-account or per-address limit.
Scenario: a free account loops `/auth/nonce` with fresh cookie values; wallet sign-in
fails for everybody for five minutes, repeatably.

**R-09 Privacy notice and terms describe the local build.**
`PlatformPages.tsx:149` says game state is saved "in the ignored data directory",
transactions are "visible on the local chain", and the terms say NFT mode uses "Anvil
test wallets … local chain 31337". The hosted preview stores game snapshots in Supabase
(`cloud_storage.py`) and uses public Base Sepolia. A privacy notice that misstates
storage and publicity is a disclosure problem, not a typo.

**R-10 Personal email and internal IDs in a public repository.**
`docs/render-deployment-2026-11-10.md:6` contains a personal Gmail address with the
Render workspace ID; `.kiro/steering/project.md` (lines about the Render account and the
GitHub owner) repeats the account name; `docs/cloud-release-review.md:3` says the
repository is public. Removing the line does not remove it from git history.

**R-11 Whole-state snapshot with no writer lease.** `cloud_storage.py:23-27` rewrites one
JSON payload holding every heist ever created; `heist_api.py:191,214,240,252,273,286`
call it several times per turn. `find_recorded` (`:28-34`) loads and parses every
namespace's payload to find one heist. Two API instances (for example during an
overlapping deploy) overwrite each other; nothing in code detects it. Growth is
unbounded on a 512 MiB container.

**R-12 Collection and market cost grows with supply.** `nft-bridge.mjs:112-119`
(`collection`) makes sequential RPC calls for every minted token; `listingRows`
(`:80-96`) reads every listing ever created. Against a public RPC at roughly 0.1–0.3
seconds per call, the 45-second limit (`nft_game.py:63`) is reached somewhere around
150–400 tokens. Collection, dashboard count and avatar picker would then fail (503).

**R-13 An image job can stay `generating`.** `candy_store.py:232-233` runs
`self.row(ident)` and `json.loads` outside the `try`; the executor swallows the
exception, so the job stays `generating`. The `except` handler's own database update
(`:265`) has the same weakness. `generate()` returns the unchanged `generating` row until
a restart marks it `uncertain` (`:102`).
