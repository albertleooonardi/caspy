## Findings

### P1 — Running API has not activated local Schnell

Repeated fresh `GET http://127.0.0.1:8000/candy/config` responses still report:

```json
{"model":"black-forest-labs/FLUX.1-dev","configured":false}
```

The response lacks the new `generation_local` field. Root configuration selects `local-schnell`, and the local runtime/checkpoint readiness checks pass. Process inspection found the original Python API PID 4314 and frontend PID 4318 still attached to launcher PID 4194, started around 20:32 on 3 November. These are observations, not instructions to terminate a future process with the same PID.

**Impact:** the running application cannot generate reward images through the intended local backend, despite the updated files and completed model setup. The user's restart acknowledgement was followed by another check; the old response remained.

**Action:** stop the original `run.sh` terminal with Ctrl+C, then run `bash run.sh` from this repository. Verify `/candy/config` reports model `black-forest-labs/FLUX.1-schnell`, `generation_local: true` and `configured: true`. Development servers were not restarted by the QA agent, per project steering.

### P2 — Judge category and exploit flag can disagree

The benign declined-story fixture received `NO_YIELD`, confidence 0.99, category `exploit_attempt`, but `exploit_flag: false`. The reward decision correctly remained ineligible. The other three fixtures had consistent categories/flags and expected outcome gates.

**Impact:** research exports and benchmark summaries could contain contradictory persuasion labels. Four cases are a smoke test, not evidence of broad judge calibration.

**Recommended correction:** validate category/flag consistency before accepting judge output, retry or mark contradictory outputs for review, and expand labeled calibration fixtures. Preserve the deterministic reward gates.

### P2 — Local image generation is slow and resource-sensitive

Earlier real inference on this Apple M3 with 8 GiB memory produced the revised candy image in 249.43 seconds. A prior render took 304.5 seconds; one v2 attempt failed after 28.92 seconds before a same-prompt/seed retry succeeded. The worker was observed using approximately 7.9 GB of memory. The transient failure's cause remains unknown.

**Impact:** long reward waits and a risk of failures under memory pressure. The single-worker setup has not been load-tested. Local generation also has no image safety classifier; provenance correctly records `safety_checker: false`.

This regression pass verified the saved image rather than repeating a four-minute render. See [local inference QA](qa-local-schnell.md) for the original visual review and runtime evidence. The revised sample is a wrapped candy matching the requested general mascot style; exact Caspy likeness is not guaranteed.
